# 现场接入与验收

## 1. 填写现场资料

将 `config.example.json` 复制为 `config.local.json`（已忽略 Git），填写：

| 配置项 | 内容 |
|---|---|
| `can_doctor_url` | 已验证的 CAN Doctor 完整 http/https 地址 |
| `teleop_script` | 使用内置适配器时填写现有遥操脚本的绝对路径；也可用 `ARX_TELEOP_SCRIPT` 环境变量 |
| `recorder_url` | 8080 录制服务根地址，默认 `http://127.0.0.1:8080`；也可用 `ARX_RECORDER_URL` |
| `save_dir` | 现有录制程序使用的本地绝对目录，不是浏览器下载目录 |
| `switch_instructions` | 开关位置、名称、开启顺序，可用换行 |
| `switch_image` | 开关照片，例如 `/assets/switches.jpg` |
| 四项 `channels` | 真实通道名、对应设备、页面正常标志、正常状态截图 |
| `shutdown_instructions` | 核实后的停止录制、保存、停止程序及断电顺序 |
| `commands` | 六项固定命令的 argv 数组 |
| `command_timeout_seconds` | 单次命令等待上限，应覆盖最长正常保存时间 |

照片和截图放在 `web/assets/`，支持 PNG/JPEG/WebP。未提供时不展示虚构图片。每路通道 `image` 可配置 `/assets/can01.jpg`。CAN Doctor 的按钮名称、Detect Devices / Start All 是否逐路操作、成功标志都要在现场核实后写进说明。

## 2. 封装已有程序

工作台不假设机器人框架或录制格式。编写薄适配脚本，将适配操作连接到现有系统。配置采用固定参数数组，不执行 shell 字符串，不接收网页任意命令。

示例结构仅演示配置格式，路径必须替换为真实文件：

```json
{
  "status": ["/usr/bin/python3", "/absolute/path/adapter.py", "status"],
  "teleop_start": ["/usr/bin/python3", "/absolute/path/adapter.py", "teleop_start"],
  "record_start": ["/usr/bin/python3", "/absolute/path/adapter.py", "record_start"],
  "record_stop": ["/usr/bin/python3", "/absolute/path/adapter.py", "record_stop"]
}
```

脚本通过现有 RPC、进程管理器或控制接口执行命令。不要让 `teleop_start` 持续阻塞，也不要将遥操主循环直接作为命令；启动现有受管理服务，待真实就绪后返回。所有命令 stdout **只输出一个 JSON 对象**，日志写 stderr；失败用非零退出码和可读错误信息。工作目录是项目根目录。

环境变量：

- `ARX_OPERATION_ID`：操作唯一编号。同一次操作的前置 status 和实际命令使用同一编号。适配器应据此实现自己的持久化去重，status 必须无副作用。
- `ARX_TRIAL`：`1` 为试采，`0` 为正式；沿用原格式，可将标记存入已有元数据。
- `ARX_SAVE_DIR`：已配置保存目录，仍应使用现有编号和文件布局，不覆写旧条目。

### 返回协议

所有成功响应必须有真实的布尔字段 `teleop_running`、`recording`。不得用“命令已发出”当作成功。

`status`：只读探测真实遥操与录制状态；录制期间必须给出当前 `recording_id`。

```json
{"teleop_running":true,"recording":true,"recording_id":"existing-episode-id"}
```

`teleop_start`：等待遥操可用，返回 `teleop_running:true, recording:false`。如果遥操已在运行，应由现有系统保证幂等。工作台会先探测，避免重复启动。

`record_start`：待录制实际启动后返回 `teleop_running:true, recording:true` 和现有程序生成的 `recording_id`。

`record_stop`：结束、写盘、关闭文件并完成现有校验后，返回：

```json
{
  "teleop_running": true,
  "recording": false,
  "saved": {"id":"existing-episode-id","path":"/absolute/save/dir/existing-episode-id"}
}
```

`path` 可以是单个文件或条目目录；必须位于 `save_dir` 下，有非空文件，`id` 必须与正在录制的编号一致。不得只返回整个保存根目录。工作台不转换格式，不生成真实设备条目的编号。

### 异常与重启

- 状态命令不得重启程序、开始/结束录制、或触发运动。网页每 10 秒核对真实状态，每 2.5 秒读取工作台状态；设备命令进行中不发起新的控制。
- 超时意味着结果未知，杀掉适配命令不保证其远端操作也停止。不要自动重试；在现有程序核对结果，并让 status 返回真实状态。
- 保存失败后，status 在确认本条已写完时也应返回上面的 `saved` 凭据，以便工作台恢复到复位阶段。状态中返回旧条目的凭据会被当前编号校验拒绝。
- 无法取得本条凭据时工作台保持错误状态。由接入人员在原系统核对并修复反馈；不要通过删除工作台状态文件绕过核对。
- 录制开始结果未知，且 status 显示已停止、没有保存凭据时，也需接入人员核实。工作台不会自行丢弃潜在数据或开启下一条。
- `.runtime/device/state.json` 保存流程、请求编号和条目索引。服务重启不重发命令；开工勾选清空。录制中或操作中重启会进入待核对状态。
- 本次计数指这个本地工作台会话的已确认正式保存数，页面刷新与服务重启继续保留，不按日期自动清零。
- CAN 人工确认不会持续监测通道。设备掉线信息需现有 status 明确报告；现场设备自带的保护和停止机制继续由现有系统负责。

## 3. 本地 HTTP 接口

- `GET /api/state`：读取工作台快照，不触发设备操作。
- `POST /api/action`：JSON `{ "action":"status", "request_id":"唯一编号" }`。
- 操作名：`prepare`、`status`、`teleop_start`、`record_start`、`record_stop`、`verify_trial`、`reset`。
- `prepare` 还需 `switches:true, channels:[true,true,true,true]`；`verify_trial` 是操作员核对文件的确认；`reset` 只确认场景复位且校验已停止录制。
- 操作同步等待设备返回，其他窗口可从快照看到 busy/saving。重复 request_id 不再执行设备命令；请求失败或断网后应先核对状态，不能重新生成编号盲目重试。
- 必须通过 `http://127.0.0.1:<端口>` 同源访问。页面不需要账号，不开放局域网。

## CAN Doctor 内嵌入口

配置 `can_doctor_url`（本机已核实为 `http://127.0.0.1:8000`），可选 `can_doctor_command` 固定 argv 和 `can_doctor_cwd` 工作目录。`POST /api/can/open` 仅启动或复用网页服务，不调用设备操作接口。启动前检查端口占用；已占用却不可访问时报告错误，避免官方启动器结束已有端口进程。

内嵌 iframe 放在独立持久弹窗，不随工作台状态轮询重载。CSP 只放行配置的目标来源；页面被目标站点禁止嵌入时，使用新窗口入口，不绕过目标站点限制。关闭弹窗不停止 CAN 服务。

本机已确认程序路径及原网页按钮名称，但四路设备对应关系与正常标志仍需现场核实。网页可打开不等于四路 CAN 已就绪，仍需操作员逐项确认。

## 内置真实遥操适配器

将 status / teleop_start 等命令配置为调用 `teleop_adapter.py`，并在 `teleop_script` 填写 `/absolute/path/to/ARX5_beta/test_remote_encoder.py`；使用系统 Python 启动，工作目录为该脚本所在目录，并传入 `ARX_RECORD_SOCKET=/tmp/arx-record.sock`。

脚本原有行为是先左右从臂回零，再持续主从跟随。网页启动前展示该行为并要求现场确认。操作员完成开关与 CAN 人工确认后才启用启动按钮。接入没有修改原遥操脚本、退出回正条件或 SDK。

status 同时检查真实脚本进程和现有录制服务 `http://127.0.0.1:8080/status` 的新鲜 telemetry，二者都满足才显示运行中。仅进程存在、启动命令已提交、或者相机预览正常，都不表示遥操已就绪。数采服务离线时报告无法核对，不假报成功。

启动结果不确定时保留进程并查状态，日志在 `.runtime/device/teleop.log`；不会重复启动已有进程，也不自动关闭遥操。当前页面的录制控制已接入现有 recorder 的生命周期；原采集页面仍在 8080，二者共享同一个录制器。

默认实际使用 `python3 server.py`。`--demo` 仅用于软件演示，其遥操运行状态是模拟的，不能用于判断实体设备。


## 真实录制控制已接通

`teleop_adapter.py record_start/record_stop` 调用既有录制服务的 `/control/record/start` 和 `/control/record/stop`，复用同一套相机、遥测、编号与文件格式。控制器不加载或调用机器人 SDK。

录制服务的 `workbench_control.py` 在执行操作前将操作编号写入 `.workbench-control.json`，重复请求不重启或重复停止条目，服务重启也不重放未知结果。结束保存需要匹配当前条目路径。

试采任务目录默认使用 `试采_数采任务`，正式任务使用 `数采任务`；可通过适配器的 `ARX_TASK` 环境变量指定任务名。现有文件不覆盖。

结束保存只等待录制器完成本条文件收尾和写盘，模式为 idle/warming，manifest 为 `pending_validation` 或 `complete` 且为真实数据、至少两帧，就返回本地保存凭据并进入复位。校验和转换复用既有独立低优先级后台队列，不阻塞下一条采集。`cancelled` 和 `incomplete` 仍不作为本地保存成功；写盘最长等待 150 秒，命令超时为 180 秒。超时继续用只读 status 核对，不重复结束命令。


实机连通性验证：本次通过工作台完成一条真实试采 `试采_数采任务/episode_000001`，556 帧，三路 MP4、action.csv、samples.jsonl 和 manifest.json 均已写入；manifest 为 `status=complete, mock=false`。保存后工作台进入 reset，遥操反馈保持新鲜。该条用于连通性验证，内容是否符合任务仍需操作员审核。

## 结束遥操

工作台顶部提供“结束遥操”按钮，调用 `teleop_adapter.py teleop_stop`。先确认没有录制或写盘，再对准确匹配的现有遥操进程发送一次 SIGTERM，由原脚本的回正退出条件决定是否退出。结束后核对进程实际消失才显示“遥操已结束”。

未回正时不强制结束、不自动回零、不持续重试；提示操作员手动回正并稳定后再次点击。按钮不是急停。结束后保留数据与试采审核状态，再启动遥操会恢复到保存后的复位步骤或原等待阶段。重新启动仍执行原脚本的左右从臂回零流程。


## 连续采集与后台处理

“本地已存正式条数”统计文件已落盘的条目，“校验通过”数量单独计算。它们不代表同一个完成阶段。后台队列持久化在各条目的 job.json 中，原录制服务的后台进程负责排队校验与转换、服务重启后的任务恢复；工作台不启动重复的后台处理器。

工作台每次读取状态时，核对已保存条目的 manifest.json 与 job.json，更新等待、校验、转换、完成和失败状态。旧条目的处理结果在下一条录制期间也会更新。转换失败仍保留原始文件，记录明确显示失败原因，不打断当前录制或阻止下一条。

工作台刷新或服务重启后，从持久文件恢复后台状态。进程未运行、条目状态无法读取时有明确提示，不假报后处理成功。后台失败任务可在原采集页面的“重试后台失败任务”入口恢复。

## 删除本条与恢复

录制中主操作区提供“删除本条”，调用现有录制器的 cancel 流程，等本条结束写盘后标为 cancelled。遥操继续运行，复位后可采集下一条；录制中作废的片段不恢复成有效数据。

最近保存卡片及每一行采集记录也提供“删除本条”。采用可恢复作废：原始文件保留，通过 `.workbench-deleted.json` 标记删除，移出本地有效条数和校验通过计数，后台队列跳过，后续校验/导出排除。已保存的完整条目可在原位置点击“恢复本条”。

若删除时后台正在处理，本次处理会在下一个检查点收尾并作废；恢复使用每条目的处理锁，后台仍在收尾时提示稍后恢复。删除不强行中断文件写入或移动正在读取的目录。已生成的历史导出文件保留；后续从原始数据重新导出会排除已删除条目。

内置 `teleop_adapter.py` 从工作台接收 `ARX_SAVE_DIR`，不再假定开发电脑的数据路径。适配器也会读取项目根目录的 `config.local.json`；直接调用时可用 `ARX_SAVE_DIR`、`ARX_TELEOP_SCRIPT`、`ARX_RECORDER_URL` 环境变量覆盖对应配置。脚本路径未配置时不会启动遥操。
