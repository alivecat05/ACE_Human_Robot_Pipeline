# 外部遥操的回正退出条件

这是操作员明确选择的退出规则，独立于录制器。录制器从不加载此模块，
网页结束录制、写盘失败、关闭页面不会触发此规则或关闭控制器。

以下为兼容外部脚本的接入方式；请先审阅本节的可选补丁，再使用实际 SDK 工作目录：

~~~bash
cd /absolute/path/to/ARX5_beta
ARX_RECORD_SOCKET=/tmp/arx-record.sock python3 test_remote_encoder.py
~~~

启动仍保留该脚本原来的双臂回零流程，应由现场操作员按既有流程启动。
此修改不新增启动动作；退出时原来的自动回零已移除。

## 操作

1. 先放好物体，用示教臂手动把左右从臂带回 SDK 六关节零位附近。
2. 等待终端显示“已回正并稳定，Ctrl+C 可退出”。
3. 按 Ctrl+C，程序切换到既有 SDK 阻尼保护，完成清理并退出。

未满足条件时按 Ctrl+C，只打印具体原因，继续遥操，不自动移动或回零。
本次退出请求被消费；后来回正不会自动退出，需要重新按键。
重复 Ctrl+C 也不会绕过条件或打断清理。普通 SIGTERM 使用相同条件。
不要把 Ctrl+C 当作急停：此处按操作员选择继续跟随示教臂。

## 判定

| 项目 | 当前条件 |
| --- | --- |
| 实测关节位置 | 左右臂各六关节，距 SDK 零位不超过 3° |
| 当前遥操目标 | 左右六关节目标也在 3° 内，且 SDK 接受 |
| 实测关节速度 | 所有关节不超过 0.1 rad/s |
| 位置稳定性 | 连续至少 1 秒，各关节位置变化不超过 0.5° |
| 反馈 | 双主臂在线；每侧六关节及夹爪电机均已收到反馈，反馈年龄不超过 100 ms |
| 反馈状态 | 无故障、离线、限位、CAN 链路断开或非有限数值 |
| 采样连续性 | 观察间隔不超过 100 ms；超时或无效反馈后重新计时 |

夹爪开度不作为回正目标，不自动开闭夹爪。阻尼保护沿用原 SDK 行为，
不代表位置锁定；退出前需要操作员确认物体和机械臂均可安全释放控制。
SDK 零位已用虚拟控制器核对为六关节目标 `[0, 0, 0, 0, 0, 0]`，
没有为此实例化真实控制器。

这些是软件判据，尚未进行本轮真机回正退出验收；不会仅凭离线测试宣称硬件已验证。

## 故障边界

已有 SDK 故障仍立即进入原有保护/退出路径；控制循环异常也尝试保护并清理，
不会等待手动回正，不会在故障退出时发送回零轨迹。
物理急停、断电和不可捕获的 SIGKILL 不受 Python 退出条件控制。
此条件防止普通退出请求误关遥操，不能承诺操作系统或硬件永不中断。

## 代码与本地补丁

- `src/arx_x5_data/teleop_exit_guard.py`：只使用标准库的判定与信号处理。
- 外部脚本目录中的旁置副本 `teleop_exit_guard.py`：内容与上述模块一致，
  系统 Python 启动旧入口时无需安装数采环境依赖。
- `integrations/test_remote_encoder_exit.patch`：相对于本轮开始时本地脚本的窄补丁，
  保留此前已有的端口、夹爪标定、SDK 下发和遥测接口。

该补丁只适用于对应版本的外部脚本，不会由安装数采包自动应用。
已应用的环境勿重复应用；应用前备份外部脚本，并审阅补丁是否匹配当前 SDK 版本。

## 已执行的离线验证

41 项回归覆盖双侧偏离、移动、目标尚未回正、旧反馈、错误反馈、离线、
未接受目标、计时中断、稳定性以及重复信号和信号处理器恢复。
另将本机实际入口置于虚拟 SDK 下执行，验证未回正请求不退出、
回正后不会消费先前已拒绝的请求、再次请求才退出、异常/故障进入保护，
以及清理过程中重复 Ctrl+C 不跳过控制器关闭。
实际遥测发送器面向不存在的录制 socket，未影响上述控制流程。
所有机器人对象均为虚拟对象，没有打开 CAN，没有执行实体运动。
